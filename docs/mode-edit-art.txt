SPIRITS EDIT MODE and COLOR EDIT MODE - drawing (SLPS-25559)
============================================================

Scope: the draw side of tasks 0x13ada0 (SPIRITS EDIT) and 0x13b1c8 (COLOR EDIT) and of
the shared widget library they call. The logic side is docs/mode-edit.txt; the widget
state machines are docs/mode-gallery.txt PART A.W. Everything below was read from the
instructions and then confirmed by work/ss6/validate_edit_art.py, which runs the original
tasks with their draw routines executing and compares the submission queue 0x68c3c0 of
every visit with src/edit_art.cpp. Statements not covered by that comparison are tagged
UNVERIFIED. Addresses are hexadecimal; coordinates are integer pixels of the 640x448
frame; colour words are written as the 32-bit values the routines pass (AARRGGBB for the
flat primitives 0x1145c0 / 0x1143e0 / 0x1147d8, see src/menu_canvas.cpp).

Native module: src/edit_art.hpp / .cpp (EditArt, EditFrame, EditPaletteBank,
drawSpiritsEdit, drawColorEdit). Tables: work/ss6/extract_edit_art.py -> edit_art.bin.

0. Draw order of the two tasks
------------------------------

  SPIRITS EDIT visit (0x13ae.. loop)         COLOR EDIT visit (0x13b3.. loop)
  ----------------------------------         --------------------------------
  17c210   depth cursor = 0, base = 0        17c210
  1825b8   frame slides tick                 1825b8
  ...      state machine                     ...      state machine
                                             13bf00   portrait object   -+ each takes one
                                             13bfd0   sprite object      | 17c228 step at
                                             13c4f8   check-pose object -+ layer 900
  20d9f8   editor (two panels + title box)   20c038   part selector (frame + tabs)
  20ef38   slot list                         20f680   swatch row
  182600   screen frame                      20fb58   sliders
  17eac8   summary plate + icons             20ef38   character list
                                             20f360   colour-number list + button icons
                                             20ef38   copy/paste list
                                             182600   screen frame
                                             2129d0   reset dialog

The submission order is not the paint order: every primitive carries a depth and the
queue is resolved by depth (section 1). The backdrop picture is submitted in the middle
of the list by 182600 and still ends up behind everything.

1. Depth cursor and layers
--------------------------
  0x12d3850 float cursor, 0x4ee54c float base. 17c210 zeroes both; 17c250(f12) stores the
  base. 17c228(z) returns z - cursor and then adds the constant 0x5f1f08 (0.1) to the
  cursor. Every widget primitive asks for 17c228(base - K) with a per-primitive layer K
  and hands the result to 114d88 (queue depth = 10000000 - z*100 + counter 3db8f4++).
  A larger K is nearer the viewer; within one K a later request is 0.1 nearer.
  The additions and subtractions on the cursor are inexact in single precision and use EE
  add.s / sub.s rounding (toward zero): after 13 steps the cursor is 1.3000001907 and the
  layer -1101.2999878, not the IEEE round-to-nearest neighbour. All other sums of these
  routines are exact (integers and halves).
  Layers: 500 flat backdrop (1817f0 kind 2); 700 bar shades (181c30, 181e88, 182118);
  800 boxes, borders, scroll bars, sliders, tabs, title plate, summary plate (800 at
  5f2028); 900 text, icons, summary icons, dialog shade, preview objects; 1000 text while
  word 4ee85c is set (17e1f0; the reset dialog), 520 while 4ee860 is set (17e200; not used
  by these scenes). 17e210 clears both words.
  The option panel of SPIRITS EDIT is drawn with base -200 (20d2e8 with a1 != 0 loads the
  float at 6647ac into the base and restores 0 at its end), which lifts the whole panel
  200 units above the category panel it overlaps.
  COLOR EDIT: the three object updates run before any widget draw and each consumes one
  cursor step whether the object is hidden or not (13bf5c, 13c100 and 13c5b8 are reached
  on the hidden paths too), so the first widget primitive of a COLOR EDIT visit sees
  cursor 0.3.

2. Box descriptor and box renderers (0x17c260 .. 0x17dd88)
----------------------------------------------------------
  17c260(F) clears a 0x30-byte descriptor: +0 style, +4 value, +c w = 1, +10 h = 1,
  +14 x, +18 y, +1c outer = ff000000, +20 inner = ffffffff, +24 fill = 80ffffff,
  +28 bar = ffffffff, +2c track = ff808080 (EditBox).

      ff800000 (seat 1); unfocused -> fill c0000000, inner ffa0a0a0, outer ff000060 /
      ff600000. The seat is 178f90().
  17c370(F, focused): outer = ff404040 unfocused, ff4040c0 focused seat 0, ffc04040
      focused seat != 0; inner = ffffffff.
  17c3d8(colour; x, y, w, h, t): hollow border, four 1145c0 rectangles at layer 800 in the
      order left (X, Y, T, H), top (X, Y, W, T), right ((int)(x+w-t), Y, T, H), bottom

      outer). Then by style: 0 -> border(outer; x, y, w, h, 5), inset 5; 1 -> border(outer;

        (x + w/2, y + i) (x + w - i, y + w/2) (x + i, y + h/2) (x + w/2, y + w - i)

3. Text layer (0x17db28 .. 0x17e428)
------------------------------------
  0x4ee548 is the text colour word; 17db28(c) stores it; 17db38(active, selected) stores
  ffff0000 / ffffffff (active) or ffa00000 / ffb0b0b0 (inactive).
  17e228(text, x, y, mode): K = 1000 / 520 / 900 (5f1ff4 / 5f1ff8 / 5f1ffc). It saves
  word 348a8c, stores (int)114d88(base - K) there (this advances the queue counter),
  calls 113828(17c228(base - K)), draws with 1135e8 (mode 0, colour word), 10a460 (mode 1)
  or 109f08 (other), with R = byte 2, G = byte 1, B = byte 0, A = byte 3 of the colour
  word, calls 113838 and restores 348a8c. An empty string still takes the depth and the
  cursor step.
  17e428(text, mode, plain; x, y): markup line. Depth as above with K at 5f2010 / 5f2014 /
  5f2018, taken once for the line. advance = 20 (mode 1) or 24. Units of two bytes; a
  zero in either position ends the line:
      "CR"           return the address behind the token (the callers ignore it)
      "MS"           if byte 43d0d6 == 0 every later unit is skipped
      lead >= 0x80   one glyph: mode 1 -> 10a710 at ((int)x, (int)(y + 2)), otherwise
                     10a1c0 at ((int)x, (int)y); x += advance
      0x20           17e228(" ", (int)x, (int)y, mode 1 ? 1 : 2); x += advance/2; ONE byte
      plain != 0     any other ASCII unit consumes ONE byte and draws nothing
      "EX"           17e228("EXIT", (int)(x+1), (int)(y+3), ..); x += 2*advance + 1; ONE byte
      icon tokens    I1..I9 -> 0..8, IA..IE -> 9..d, IW e, IH f, IZ 27; G1..G9 -> 10..18
                     (dx -1, dy -2); L1 L2 -> 1f 20 (dy 5); R1 R2 -> 21 22 (dy 5); SC 2d;
                     ST 1e (3, 2); SL 1d (3, 4); BO 19, BX 1a, BT 1c, BS 1b (2, 3);
                     BP 23 (2, 1); OR 2a; PL 29.
                     w = 17e038(icon; x + 1 + dx, y + dy, 17c228(base - 900));
                     x += w; x += dx + 3. The icon layer is 900 whatever the text layer.
      other ASCII    consumes ONE byte
  17e038(n; x, y, z): 0 for n == -1, n == 5d, and n == 2d while byte 43d0d6 == 0;
  otherwise 17df90(n < 33 ? slot 2e : slot 5, record 4ee6b8[n]; x, y, z), returning the
  record width. 17df90 clears the additive latch (1142c8), sets 3db900 = ffffffff and
  submits 113f98 with the record rectangle unscaled.
  Icon records 2e..32 (slot 2e) are the part labels of COLOR EDIT; 33..5d (slot 5,
  ps2_gage_1_2_3_all) are the spirit summary labels.

4. Screen frame 0x1822a0 (EditFrame)
------------------------------------
  State and requests are as in A.W (W.7). Points settled by the binary for the layouts
  used here:
  - 1822a0 constructs the title bar with 181d70(-1), which already configures its slide
    (0,-0x90) -> (0,0x10) and sets the "configured" word; later layout changes use 17f410
    (end points only, no snap).
  - Backdrop kind by layout (182318): 0 -> 1, 1/2/3/5 -> 0, 4/7 -> -1, 6/8/9/10 -> 1.
    Kind 0 is 1ce628 (picture only), kind 1 is 1ce570 (picture and animated overlay),
    kind 2 a flat ff000040 rectangle at layer 500. Both edit scenes use kind 0.
  - Title plate index (181d70): layouts 0..10 -> 2, 7, c, c, 6, 9, e, d, f, f, a of the
    17 records at 4c7660 (slot 2e). SPIRITS EDIT (layout 1) -> 7, COLOR EDIT (2, 3) -> c.
  - Key-hint bar 181910: layouts 1, 2, 3 -> size 0x140 x 0x1c, text offset (0x1a, 2),
    text 5f22c0, slide (0x2d0, 0x158) -> (0x140, 0x158) for either seat. Layouts 4, 7 and
    5, 6, 8, 9, 10 mirror by seat (seat 1 slides in from the left to x = 0). Layout 0
    changes only the slide, with the visible position as its "retracted" end.
    Layouts b, c, d (second bar): (0x2d0, 0x13c) -> (0x140, 0x13c), texts 5f22f8, 5f2328,
    5f2318.
  - 182600 draws, in order: backdrop; title bar: 17eed8(x, y, layer 700, 640, 48),
    plate at (x+0x10, y+0xc) layer 800, optional text 17e428(mode 2) at (x+0x168,
    y+0x24); message bar: 17eed8(x, y, layer 700, 640, 48), text 17e428(mode 1) at
    (x+0x10, y+0xc); first and second key bar: 17eed8(x, y, layer 700, w, h), text
    17e428(mode 1) at (x+dx, y+dy). Before each text the colour word is set to ffffffff.
    Bars are drawn at their slide position whether open or not.

8. COLOR EDIT preview objects and palette path
----------------------------------------------
  The three objects are battle objects (0x11e2e8 + 0x11d528) and are submitted through the
  character draw path (docs/character-draws.txt), not through the menu queue.
  Per visit (after 17c210, before the widget draws):
    13bf00(obj1, portraitVisible, colour): hidden (flags +104 |= 2) unless the argument
        and word 124a180 are both non-zero; when shown with a loaded resource (+c0 != 0)
        and bit 0 of the previous flags clear: 11d908(obj1, 3, 1, 0). Always: flags |=
        0x200, 11dff8(obj1, 17c228(base - 900)), +20 = colour, 11d6c8, 11d868, 11d730.
        (Correction to mode-edit.txt 3.8: the tested flag is bit 0, value 1.)
    13bfd0 / 13c4f8: position, action and flip as mode-edit.txt 3.8; both always end in
        +20 = colour + 0x10000, flags |= 0x200, 11dff8(obj, 17c228(base - 900)), 11d6c8,
        11d868, 11d730.
  So the depths of the three objects are -900, -900.1 and -900.2 (EE rounding), in front
  of the widget boxes (layer 800) and interleaved with their text layer (900).
  colorEditPreview() returns the three requests (EditPreviewObject): hidden flag, flip,
  fighter, action and zero-based start record, position (+40, +44), depth and the palette
  word +20. The portrait's action is driven by the ObjectAction requests of the logic
  module (11d908(obj1, 3 or 4, 1, 0)) and by the 11d908(3) above.
  Palette: the draw path calls 115d40(key, bank). EditPaletteBank is that routine for
  every key (owner bits 10000 / 20000, selectors 40000 / 80000; mode-edit.txt 3.2) over
  identity 439a48 / reference 439aa8 / busy 439b08 and the CLUT store 43ab70:
      lookup  first entry with busy == 0 and identity == tag -> reference = 1, return row
      alloc   first entry with busy == 0 and identity == -1, else first with busy == 0 and
              reference == 0, else -1; the first colour of the group is cleared in the
              SOURCE table; 116478 copies the sixteen colours to store[row*16 ..] and
              marks them 16-bit
      rows    5dd5c8 = {16..31, 12..15, 8..11}
      1159d0  identity = -1, reference = 0, busy = 0
      113aa8  per-frame entry: reference = 0 (so an entry not requested during a frame is
              evictable in the next)
  13ca58 pokes the edited colour into store[row*16 + index + 1] of the row it resolved,
  which is the row the sprite samples in the same frame.
  Object stores read for this slice (static, callees not ported):
    11d570(obj, 0xb, x, y, flags) -> 11fed0 -> 11fef8(obj, slot 1, action 0, x, y, flags):
        +c = +10 = slot, +14 = resource id of the slot (word 46a9a0[slot], the fighter),
        +1c = fighter*5, +24 = 0, +40/+44 = float(x), float(y), +38 = flags | 10000000,
        +20 = +28 = 0, +30 = 0x100; then 11d570 sets +cc = 0xb.
    11d668(obj, id, x, y, flags) -> 1202c0 -> 1202e8: +14 = id, +1c = id*5,
