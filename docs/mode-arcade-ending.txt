ARCADE ENDING SCENE (SLPS-25559): per-character ending 182968 / 182a98, gallery ending viewer path
182ce0, staff roll 19c1c8
==================================================================================================
Native port: src/arcade_ending.hpp / .cpp (EndingData, EndingPlayback, ArcadeEnding, StaffRoll,
EndingArt, drawEnding, layoutEndingPage). Data: work/ss6/extract_arcade_ending.py ->
arcade_ending.bin (+ outputs/ss6-feasibility/arcade_ending_tables.json). Evidence:
work/ss6/validate_arcade_ending.py -> outputs/ss6-feasibility/arcade_ending_validation.json.
Everything below is OBSERVED in the disassembly and compared against the original in Probe unless
marked [INF]. This document supplements docs/mode-arcade-demos.txt section 1 and corrects it
where noted.

1. Scripts as data
------------------
Pointer table 4eefe8 holds 50 functions; entry 43 (19c1c8) IS the staff roll. Each function is
branch-free straight-line code (the validator asserts that no branch / jump other than the calls
of the 31 primitives executes inside it). extract_arcade_ending.py decodes each function with a
constant tracker into records {opcode, six argument words}; floats are kept as IEEE bits,
strings as pool offsets, scene objects (4ef0d0 + 138*k) as k. Inline "sw" into a scene object
becomes the pseudo opcode ObjectStore {k, field offset, value}. Asset layout: see the
extractor docstring. Totals: 10394 records (9757 primitive calls, 637 object stores), 3042
distinct strings. The validator executes every original function whole with the primitives
replaced by return stubs and requires the intercepted call/argument stream (register a0..t1,
f12..f14, string contents) and the stores to equal the asset records.

----------------------------

                   3ebf20 = 3ebf24 = 0; 3ec73c = 0; 4eeef0 = -1; 182858();

                   112a70(fa1), 1e7ad0(); gallery modes (g+0 - d < 2): 1ce478(),

  CORRECTION (spec 1.1 "=> with 43d052 != 0 no script ... executed"): the fade-out 1a1830(0, 4)
  and the 64-visit wait 1a1740(40) still run with 43d052 != 0 (bnel to 182ba8 executes them);
  only the script call is skipped. Native: begin(..., alternateText) keeps the two records.
  Every blocking primitive is a loop { 1a2118 (portraits); body; 1a2218 } where
  1a2218 = pad = 118128(4ef0c4); 1a2158(); then (582a68 == 0) the abort test on pad+4.
  1a2158 = 10add8 binds; camera 4a2a58 += (float)4efa90, 4a2a5c += (float)4efa94; 120ce0 for

3. Primitives and renderers
---------------------------
  As in docs/mode-arcade-demos.txt 1.3 (verified). Additional observations:
  - 1a1b00 msgShow: an unknown renderer id draws nothing and never completes (s1 = 0); hold
    0xb4 counts only visits on which the page is complete; mask 707 completes the page
    (s3 = 2710) or ends a complete page.
  - Renderers 1..5 reset 3d3ab0 and count glyphs through 113028 (1130f8 / 1131d8); while
    3ec73c is set (fade blank) the glyph submitters return before counting, so a page never
    completes during a full fade.
  - 1a1fe8 rollShow: the hold decrements only when the PREVIOUS visit drew every glyph it was
    allowed (prev 3d3ab0 < k/4); y0 = f2 - 14*count, line pitch 1c, x = 140 - 6*strlen.
  - 1a1ed0 rollScroll: total = count*1c + 10 + n visits, 3d3aa0 = -1, offset min(f, count*1c+10),
    a line is drawn only when (unsigned)(y_top + 1f7) < 1f7.
  - Balloon (renderer 3): 113f98 of sheet 1f/20 with the 108118 size-1 UV clamp (512x512).
    Balloon sheets are compared as queue entries only (not painted).
  - Portrait sides: 1a22a8 (rectangle c0404040 + slot 22 if id < 31) and 1a2380 (mirrored,
    slot 23); CLUT 116478(c0 | 1c0, 40, pvp + 180).
  - Background loader 1a4a98(n): n < c calls the battle stage loader 50e080[n] (scripts use 9
    and 10 = the arcade stage of the fight just won) [the stage itself is NOT drawn by this
    port]; c <= n < 64 -> ed_bg((n-c)/2+1) half (n-c)&1; n >= 64 -> table 50e0b0. Picture task
    1a4c20 (priority 10, tag fa1): one 113f98 of slot 4, v origin 1 or 482. A task created or
    killed in a visit changes the next frame (the dispatcher lists the tasks first).
  - ed_bg19: named only by table 50e0b0 entries 0x68 / 0x69, which no script uses. It is not
    a member of SAM_DATA.BIN: the archive directory inside the ELF lists ed_bg18 then ed_bg20,
    and every "ed_bg" byte string on the disc image (47 hits) lies inside SLPS_255.59. The
    file does not exist on this disc; unreachable, so nothing is lost.
  - Fade registers: 113aa8 latches 3ec73c (flash counter 3ebf24 or level 100 in mode 2);
    113b28 submits the full-screen quad of 3ec730 when latched and 116588 integrates
    3ec734 += 3ec738 clamped by 3ebf1c / 3ebf20. 117180 sets per-entry tone flags 3ebf30,
    1174b8 bakes the current fade into the source CLUT, 117438 saves it (staff roll only).
  - Objects (4ef0d0, 8 x 138 bytes): 120378/1202e8/120d10 start, 120390 action, 120428
    velocity, 120438 colour steps (121308), 120ce0 per visit (120618 motion, 120880 -> 1207e8
    object queue 479250, 120ac8 ACT clock). Resource "99a" is bound to both resource slots;
    ACT sound commands go out through 1e8298 (EndingEvent::ObjectSound). The native engine
    submits the same 78-word queue records (EndingFrame::objects); the character renderer
    1208b0 / 121b80 is not part of this port.

4. Arcade coroutine 182d30 and STAFF ROLL 19c1c8
------------------------------------------------
  seat 4ef0c4 = (g+0 == 1) ? 0 : 1 (the bne delay slot stores 1); s = 456890 + 30*seat;
  byte 43d058+81+s.+8 = 1 and byte 43d058+47+s.+0 = 1 (both written); 4ef0c8 = s.+4;
  1c9830() (name entry task 1c9928, priority 14); 182a98(s.+0); 112a70(fa1); 1e7ad0();
  if setjmp(4efb40) == 0 && byte 43d052 == 0: 19c1c8();
  112a70(fa1); 1e7ad0(); g+34 = 1; 1252f0(1, 1, 182a48, 138340); forever {1a2118; 1a2158}.
  START during the staff roll longjmps to 182e18 with v0 != 0 -> straight to the exit. The
  staff roll is entered on the same visit on which 182a98 returns (no yield in between).
  19c1c8: loadBg0(0x32) (ed_bg20 half 0), 117180(200, 400, 2), 1170c8(0), 117108(0, 80),
  bgm(4, 1), camera, then roll groups; it has no register reset of its own.
  Name entry: created by the first visit, so the task handler first runs on the second frame;
  the harness and the native order are "name entry task, coroutine" (same priority 14,
  created later).
  Destructor 182a48: g+30 = 0 (the challenger inhibit set by 182968), score reset (1bc1a8),
  1c4e08 start-hold clear; ArcadeEnding::leave.

5. Gallery path
---------------
  182968 with g+0 in {d, e}: coroutine 182ce0: 4ef0c4 = 178f90(); loop { 182858();
  c = 13f4a8(c, 1) (selection UI, src/console_gallery.* EndingViewer); 4ef0c8 = 0;
  182a98(c) }. Playback exits by 404 (sound 25) or naturally; afterwards 1ce478 re-enters the
  menu backdrop and 4eefd4 = galleryRow() (native: EndingEvent::MenuBackdrop, a = row). The
  return visit has no yield of its own: the same visit continues into 182858 and 13f4a8, whose
  drawing completes that frame (the validator compares its primitives, not its pixels).
  START does not leave a gallery playback.

6. Differences from ArcadeSession::follow() (written from the static spec)
---------------------------------------------------------------------------
  - The original exit is 1252f0(1, 1, 182a48, 138340); follow() requests (2, 0, ...).
  - The ending writes TWO clear-record bytes: option 0x81 + spirit and option 0x47 + character;
    follow() writes only the second (markEndingSeen).
  - g+30 is set on entry and cleared by 182a48; g+34 = 1 is written just before the 1252f0.
