2. Common task structure (VERIFIED for stages 0, 1, 2)
-------------------------------------------------------
A task draws, in a fixed order: stage-specific backdrop code, a loop over 0x48-byte object
rows, then stage-specific foreground/floor code. Row layout:

  +00 texture slot     +04 flags          +08 x  +0c y  +10 z      +14 sx  +18 sy
  +1c piece count      +20 pieces         +24 (helper argument)    +28 animation {state*, table*}
  +2c prologue type    +30 mesh params    +34 +38 +3c shadow position

Flags select the helper: 1 -> 1a6210, 2 -> 1a66b8 (scaled), 4 -> 1a6460 (mirrored),
8 -> 1a6b08 (mirrored, scaled), 0x40 -> 1a4e80, 0x80 -> 1a4ee0 (mirrored); 0x10 and others are
stage specific. 0x100 marks an animated row. Prologue type 1 -> shadow 1a5428, 5 -> 1a5d40,
6 -> 1a5f68 (mesh shadows). Pieces are 24-byte records {u, v, w, h, flags, -}; record zero is
the bounding rectangle when a row has more than one piece. Piece flag 0x200 submits that piece
with alpha mode 0.

Animated rows: state {+0 elapsed 8.8, +4 picture, +2c step, +34 piece counts, +84 piece
tables per picture}; table records {picture, duration 8.8}, negative picture restarts at record
zero. The remainder carries but only one record is consumed per visit (src/stage_clock.hpp).
Two rows may share one state object and then advance it twice per visit.

Render state: 3db900 = vertex color (-1 white), 3db8fc = alpha mode handed to 1149d0 as
argument 3 (1: halved vertex alpha is used; otherwise alpha is forced to 0x80). 1149d0 copies
vertex zero's color to the whole strip and halves every channel. 114d88(z) returns
10000000 - 100 z + counter and increments the counter (3db8f4, reset to 100 by 114e80);
114dc8(z) returns the same key without incrementing. Helpers that go through 113f98 cull
against the 640x480 buffer first and only then take an order number; direct 1149d0
submissions neither cull nor count.

50e04c != 0 hides the stage: helpers return early, the animation clocks still advance.

Shared leaf helpers and their native counterparts (src/stage_draw.hpp, struct Projector):

  1a6210 / 1a6460 / 1a66b8 / 1a6b08   sprites()      command kinds 1, 2
  1a51b0 / 1a52e8                     sprites()      kinds 1, 2 (single float rectangle)
  1a4f40 (via 1a5428)                 shadow()       kind 3
  1a5890 (via 1a5868)                 floor()        kind 4
  1a5d40 / 1a5f68                     meshShadow()   kind 5
  1a8768 / 1a88e8 (stage 1 only)      floor(full)    kind 6
  1a4cb8 / 1a4d98 (via 1a4e80/1a4ee0) plain()        kinds 7, 8
  1a6f90                              quarter()      kind 10
  113f98                              rectangle()
  1a5ad0 / 1a5b38 / 1a5ba0            save / restore / shift the projection (copy the camera)

Kinds 9 and 11.. are private to the stage that exports them.

3. Tooling
----------
work/ss6/stage_fixture.py            shared Probe fixture; per-stage config in stage_fixture_NN.py
work/ss6/extract_combat_stage_n.py   --stage N -> extracted/resources/combat_stage_NN.bin
                                     (commands per group = prefix, each row, suffix; one variant
                                     per picture; asserts camera independence with 3 cameras)
work/ss6/validate_combat_stage_n.py  --stage N [--visits 900]: one continuous run, whole task
                                     per visit; compares complete sorted 1149d0 lists, order
                                     counter, library seed, and sampled 640x480 pixels.

Native: src/combat_stage_NN.{hpp,cpp} hold the per-stage state (clocks, state machines) and
the draw function in original submission order; CombatStageState owns one state per stage;
CombatStage loads the command file and dispatches. Stage 0/1 keep their earlier files.
