Common fighter projectile engine (16d9c8 / 16dcc0 / 16d2b0 / 16def0 family)
==========================================================================

Scope: static reverse engineering of the pinned ELF work/ss6/extracted/SLPS_255.59
(MIPS R5900 LE) with analyze_elf.py, delay slots accounted for. Every statement
was read from the disassembly unless marked INFERRED (meaning assigned from
usage) or UNVERIFIED. No Probe comparison has been run for any function in this
document; nothing here is runtime-verified. Script-row semantics are in
docs/script-engine.txt (sections 3, 9); Mina-specific handlers in
docs/mina-callbacks.txt (sections 7-10). This file supersedes the "16dcc0
internals UNVERIFIED" note in script-engine.txt section 9.

Conventions
  actor   StateEntryActor (actor[0] = body PlayerObject, actor+4 = companion,
          +0x23c flags23c, +0x244 flags244, +0x248 flags248, +0x26c script
          variant = callbacks260[3], +0x28c registry28c[0..12], +0xa10
          character, +0xa24 player slot, +0xf17 byte counter (Mina)).
  cb      3-word callback context built by 169780/169798(cb, actor):
          cb[0] = actor, cb[1] = 1400a8(actor.a24) (opponent actor),
          cb[2] = actor.268.
  o       pool object (AuxiliaryObject words; native names in section 11).
  ended   o.c0 != 0 && !(o.104 & 1)   (ACT finished and no request pending).
  cam     140040() = *(0x4d3d00)+0x34 camera block: cam.10 int left edge,
          cam.14 int right edge, cam.1c int upper bound (INFERRED from 146a50 /
          146a98 usage), cam.0c float width.
  req(o,act,imm,force)  11d908 = AuxiliaryObjects::request.
  stop(o) 11d990 = AuxiliaryObjects::stop (clears 4c/50/54/5c/60, 104 &= ~0x140).
  hold(t) 147530(task): task[0] = 0x147540. 147540 only does o.104 &= ~0x100
          each visit (native AuxiliaryObjects::releaseHold). It never frees;
          removal is via o.108 bits (section 7).
  RNG(n)  112300(n) = GameRandom bounded draw.

--------------------------------------------------------------------------------
1. Where the engine runs in the frame (140270)
--------------------------------------------------------------------------------
140270 (battle object phase), relevant tail, in exact order:

    1494f0(actor0), 1494f0(actor1)                       // actor/input/script callbacks
    for i in 0,1: 149918(actor_i); 146ef8(battle+0x29c+0x108*i, 0x30)
                                     // body action commit, then THAT seat's
                                     // object callbacks (16def0 etc. run here)
    146ef8(battle+0x14c, 0x40)                           // common registry callbacks
    for i in 0,1:
        11d8e0(body_i)               // if body.104 & 1: 11dbf0 commit requested ACT
        16d9c8(actor_i)              // projectile / attachment spawn (section 2)
        body_i.104 &= ~0x8000; body_i.104 &= ~0x10000
        1474a0(battle+0x29c+0x108*i, 0x30)
                                     // per registered object: 16dba0(o) (section 9),
                                     // then o.104 &= ~0x18000
    147128(...) x2, 147128(battle+0x14c,0x40), 141568, 141740, ...

Earlier in the same function (1403cc) 142f30(battle) computes the
out-of-view bit 104:4 for both bodies and every registered object (section 8).
Contacts (which write o.100 / o.104 contact bits) run before 140270's object
callbacks, so 16def0 sees the same frame's contact results. INFERRED from
native_match.cpp ordering; the contact function itself is out of scope.

  +-----------+   +-------------------+   +-----------------+   +---------------+
  | 1494f0 x2 |-->| 149918_i + 146ef8_i|-->| 146ef8 common   |-->| per seat i:   |
  +-----------+   | (i = 0 then 1)    |   +-----------------+   | 11d8e0,16d9c8,|
                  +-------------------+                         | clear 18000,  |
                                                                | 1474a0_i      |
                                                                +---------------+

Consequences
  - A projectile created by 16d9c8 is first visited by its callback on the
    NEXT frame (146ef8 already ran). Its first ACT is a queued request
    (req(...,0,1)), so 1474a0's 16dba0 in the birth frame normally sees no
    0x8000 marker on it.
  - Native (native_match.cpp ~1076-1140) runs commitAction for BOTH seats
    before auxiliaryPhase(Callbacks) visits registries 0,1,common. The original
    interleaves 149918(p0), objects(p0), 149918(p1), objects(p1). Seat-0 object
    callbacks that read seat-1's body state (e.g. 16f510 homing, 16c760-style
    owner-ACT reads only read the OWNER) could observe a different p1 ACT.
    DISCREPANCY (impact UNVERIFIED).
  - Native then does commitRequested (=11d8e0), the spawn branch, flag clear and
    the 1474a0 scan per seat, matching the original order.

2. 16d9c8(actor) - ACT spawn marker reader
--------------------------------------------------------------------------------
    body = actor[0]
    if (body.104 & 2)          return 0           // hidden body
    if (!(body.104 & 0x8000))  return 0           // no ACT spawn marker this frame
    if (body.10c != 0 || (body.104 & 0x10000))
        return 16dcc0(actor, 1, body.10c, 0)      // plain ACT attachment (mode 1)
    opp = 1400a8(actor.a24)
    reg = actor+0x28c
    if (reg[11] == 0) return 0                    // no running script
    row  = reg[11] + 20*reg[0]
    mode = row[0x0d]; id = (s16)row[0x0e]; type = row[0x13]
    if (mode == 0) {
        if (type == 0x1f) { if (actor.f17 == 0) return 0; actor.f17-- }  // u8
        o = 16dcc0(actor, 0, id, actor.26c)
        if      (type == 0x23) o.x = opp.body.x          // no NULL check on o
        else if (type == 0x14) 16dcc0(actor, 0, id + 1, 0)
        else if (type == 0x17) { 16dcc0(actor, 0, id, 1); 16dcc0(actor, 0, id, 2) }
        return o
    }
    if (type == 8) return 16dcc0(actor, mode, id, 0)
    return 16dcc0(actor, mode, id + actor.26c, 0)       // modes 2,3,4 add variant to ACT

Notes
  - Mode 0xff rows reach 16dcc0 with mode >= 5 and spawn nothing.
  - There is NO state gate: any body ACT record carrying the 0x8000 marker
    while a script is registered fires the CURRENT row. Native gates on
    stateTable()==1 && state>=64 per character (section 12).
  - The (flags104 & 0x18002) tests in native_match.cpp are equivalent to the
    2 / 0x8000 / 0x10000 tests above.

3. 16dcc0(actor, mode, id, variant) - spawn dispatcher
--------------------------------------------------------------------------------
    body = actor[0]; 169798(cb, actor)        // cb[0..2] (169780 not called)
    switch (mode) {                           // table 0x5f1598, 5 entries
    case 0: o = 16d2b0(cb, id, variant)       // descriptor projectile (section 4)
    case 1: o = 16ddc0 path:

                if (t[0]==id || t[1]==id || t[2]==id) { o = 0; break }

    case 2: o = 16c4e0(cb, id, 0, 0)          // owner-following effect
    case 3: o = 16c408(cb, id, 0, 0); o.108 |= 0x8000
    case 4: o = 16d0e0(cb, id)                // section 6.4
    default: o = 0

    if (o && (body.104 & 0x8000)) {           // "16dd44" (label inside 16dcc0)
        o.x = (body.38 & 0x80000) ? o.x - (float)body.110 : o.x + (float)body.110
        o.y = o.y + (float)body.114

  - The offset uses the BODY's mirror bit and body.110/114 (ACT attachment
    command words), not the object's. It is applied AFTER group placement, so
    groups 5/6/7/13 positions (camera edge, opponent x, cam.1c) also receive
    the attachment offset. Ported as AuxiliaryObjects::applyAttachmentOffset
    (auxiliary_objects.cpp:169, annotated "16dd44").
  - 16fb50 (character-22 mirror match only) fills 12d26a0: both slots -1,
    then ACTs 508..513 are split 3/3 between the slots with RNG(2) per ACT
    (forced into the other slot when one already has 3). A character-22
    player never shows the mode-1 attachments listed under its own slot.
    Native spawnActAttachment has no such filter (character 22 not ported;
    DISCREPANCY to record before admitting character 22).
