# 素材替换

游戏从一个基础素材目录读取文件，并允许用覆盖目录中的同名文件替换其中任意一个。基础目录保持不动，删除覆盖目录即恢复原状。

## 覆盖目录

```sh
./select.command --mod mods/my-mod                       # 可重复，靠前的优先
SS6_MODS=mods/a:mods/b ./select.command                  # 等价的环境变量形式
```

查找规则：

```
加载器请求 assets/<文件名>
        │
        ▼
依次检查每个覆盖目录下是否存在 <文件名> ──是──▶ 使用该文件
        │否
        ▼
使用 assets/<文件名>
```

- 只按文件名匹配，覆盖目录是平铺的，与基础目录同构。
- `--mod` 指向不存在的目录会直接报错，避免静默读取原版数据。
- 玩家存档（`--save`）不参与覆盖。
- 探针和回放工具同样遵守 `SS6_MODS`；做原版对比验证时不要设置它。

## 贴图

`.tex` 是无文件头的 8 位索引图，可选在末尾附带 256 项 32 位调色板；独立的 `.pal` 是 256 项 16 位（512 字节）或 32 位（1024 字节）调色板。尺寸和调色板顺序不在文件里，`ss6tex.py` 解码时把它们写进 PNG 旁边的 JSON，编码时读回。

```sh
A=outputs/ss6-feasibility/native-viewer/assets
python3 tools/assets/ss6tex.py decode $A/bg_title00.tex -o art/bg_title00.png
# 用支持索引色的编辑器修改 art/bg_title00.png
python3 tools/assets/ss6tex.py encode art/bg_title00.png -o mods/my-mod
./title.command --mod mods/my-mod
```

`python3 tools/assets/ss6tex.py verify $A --scratch <空目录>` 会把目录内每张贴图解码再编码并逐字节比较，用来确认工具对当前数据集无损。

编辑时的约束：

- PNG 必须保持索引色模式。游戏按编号引用调色板项，若干画面还会在运行时换调色板，真彩色图无法导入。
- 不要改变图片尺寸。加载器按原版尺寸校验文件大小，尺寸不符会在启动时报错。
- 16 位调色板每通道只有 5 位，透明度只有 1 位；编码时会截断到该精度。
- 没有同名 `.pal` 且无内嵌调色板的贴图（如 `sakura.tex`）的调色板来自别处（由使用它的加载器决定），解码结果用灰阶预览，编码时只写回索引。
- 少数贴图页是每字节两个 4 位像素，或宽高不是工具推断的默认值；这类需要用 `--width` 指定，4 位页目前不支持。

## 角色精灵

每个角色资源 NN 的图像由三个文件组成：`idx_NN.bin`（图像号到记录的索引，含调色板库号）、`map_NN.bin`（每张图的 8 像素图块排列）、`chr_NN.bin`（4 位图块）。颜色来自所有角色共用的 `pal_all.bin`，每组 16 色，组号为 `调色板键 * 32 + 库号`，默认键为 `资源号 * 5 + 配色号`。

```sh
A=outputs/ss6-feasibility/native-viewer/assets
python3 tools/assets/ss6sprite.py export --assets $A --resource 0 -o art/haohmaru
# 修改 art/haohmaru/NNNN.png
python3 tools/assets/ss6sprite.py import art/haohmaru --assets $A -o mods/my-mod
./battle.command --mod mods/my-mod
```

导入时的行为：

```
逐张比较 PNG 与原图
   ├─ 像素相同 ──▶ 该图的 idx/map/chr 数据原样保留
   └─ 像素不同 ──▶ 新图块追加到 chr 末尾（已有的相同图块复用）
                   新记录追加到 map 末尾，idx 指向新记录
调色板与原组不同 ──▶ 只改写 pal_all.bin 中对应的 16 色组
```

约束：

- 每张图最多 16 色，索引 0 是透明色；颜色精度为每通道 5 位。
- 宽高必须是 16 像素的整数倍。工具接受改变尺寸，但部件的摆放位置由 `pil_NN.bin` 和动作数据决定；改尺寸后的显示效果尚未在游戏中验证，建议保持原尺寸。
- 同一库号的所有图共用一个调色板；两张图给出不同的调色板会报错。
- 调色板修改只作用于导出时选择的那一个配色（`--colour`，默认 0）。其余配色各有自己的键，需要分别导出修改。
- `pal_all.bin` 是全体角色共用的单个文件；多次导入到同一个 mod 目录时会在已有文件上累加。
- 个别图像记录的尺寸不是偶数图块（原版运行时同样不支持），导出时跳过并列在 `sprites.json` 的 `skipped` 里。

## 目前可以替换什么

| 素材 | 文件 | 可编辑格式 | 状态 |
|---|---|---|---|
| 界面、背景、立绘、场景贴图 | `*.tex` / `*.pal` | 索引 PNG | 可用，往返无损 |
| 角色精灵图像与配色 | `chr/idx/map_NN.bin`、`pal_all.bin` | 索引 PNG（每张图一个） | 可用，见下节 |
| 精灵部件布局 | `pil_NN.bin` | 无 | 只能整文件替换 |
| 动作与判定框 | `aid/act/jdg_NN.bin` | 无 | 同上，格式见 action-format.txt |
| 音乐、音效 | `*.vb`、`vs_sounds_NN.bin` | 无 | 同上 |
| 数值表 | 其余 `*.bin` | 无 | 同上，字段含义见对应专题文档 |

整文件替换始终可用：把同名文件放进覆盖目录即可，但文件必须满足加载器检查的大小和布局。

## 霸王丸水墨预览

项目根目录的 `ink-battle.command` 构建本分支的 viewer，然后启动资源 00 的双人对战。人物和武器分别跟随原版 PIL 图像、镜像、图层顺序及 ACT 阶段时钟。常规持刀待机和出招都通过图像号查找 2× 图层，身体与刀分别绘制。最终对战画布仍为 640×448。

`mods/ink-idle/haohmaru_actions.ink` 包含 460 张身体等重绘图像和九张配套待机刀图。待机的手与刀在同一画布上对齐，再按原版图层拆分。`tools/assets/ss6ink_parts.py` 从玩家本机基础素材重建另外 400 张独立图像的轮廓和颜色覆盖率，主要是刀、刀光与碎片。启动器将合成的 869 图包缓存在 `work/ss6/ink-parts`，源图或制作工具变化时重新生成。仅传 `--mod mods/ink-idle` 会加载重绘图，独立刀光等使用基础素材。其他角色和全局效果资源沿用现有覆盖规则。

动作包保存每张图的编号、原图的 16×16 分组尺寸和每组的存在标志。非空组由 32×32 个双字节采样组成，第一字节的低、高半字节是两个 CLUT 索引，第二字节的低、高半字节分别是混合权重和覆盖率。显示时从本帧的角色调色板取色。仅在缺少对应待机身体图层时使用旧 RGBA 整身画稿。当前启动器以基础素材目录作为刀光的输入。
