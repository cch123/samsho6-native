Pause menu, KEY CONFIGURATION and SKILL LIST drawing (SLPS-25559) - what src/pause_art.* ports
==========================================================================================

Scope: the submissions (queue 68c3c0 entries) of the in-battle pause task 1d9e10, of the
KEY CONFIGURATION coroutine 13ce08 and of the SKILL LIST coroutine 13d680.  Logic is in
docs/mode-pause-menu.txt and docs/mode-skill-list.txt; the window library (17c210..17f090,
1817f0..182600, 20ef38, 17e228, 17e428, 17e038) is documented in docs/mode-gallery-art.txt
and used unchanged through GalleryArt.  Everything below is OBSERVED in the disassembly and
confirmed by work/ss6/validate_pause_art.py unless marked otherwise.
Colour words are AARRGGBB (the convention of src/menu_canvas.hpp).

  writes them besides 1c1528 (the two words are referenced only from 1daca8): the pulse is
  not reset when the menu opens and continues where the last pause left it.

4. 109de8 - the "backdrop" of a guide window over a battle
----------------------------------------------------------
1817f0 (first call of 182600): backdrop kind -1 -> nothing; 17ea48() == 0 -> 109de8().
109de8 submits NOTHING to the queue.  It sets bit 4 of the frame flag word 3451c8.
    107208 (start of a frame): 3451cc = 3451c8; 3451c8 = 0.
    107280 (frame flush) and 1074b0 (re-send of the previous lists): when the flag is set,
        109d70 / 109d98 = 109c40(buffer, 1, [34516c] ^ 1) is sent before the display lists.
    109c40 links four prebuilt GS register words of table 348d00 (index 16 a1 + 8 a2):
        BITBLTBUF (50), TRXPOS (51) = 0, TRXREG (52) = 640 x 224, TRXDIR (53) = 2 (local ->
        local).  a1 = 0 copies frame buffer block 0 -> 1a40 and 8c0 -> 2300 (save), a1 = 1
        copies 1a40 -> 0 and 2300 -> 8c0 (restore); a2 selects the field buffer.
So the flag asks for the frame buffer saved in GS memory to be copied back before anything
of the frame is drawn.  The save (109d00(0, 2)) is issued by the system screens (1019bc,
101f68, 10cae8.., 111c20, 1b6548), not by the pause code.
INFERRED (not executed: no GS model): in a battle the restore is invisible, because the
stage and the fighters are submitted again on every paused frame and cover the whole
picture; the child windows are then composed over the live (paused) battle frame.  The
native functions return the request as a bool; the validator compares it with bit 4 of
3451c8 on every visit.
The validator found the flag set on every visit of both child windows in the battle modes
and never in mode 0x11 / 0xd (page backdrop through 1ce628 / 1ce570 instead).

6. Not ported / not verified here
---------------------------------
  * GS rasterisation: frames are compared against the reference painter of
    validate_menu_canvas.py (pixel-centre sampling of the queue entries).  The colour ramp
    of the 17e0b0 strip is painted on both sides as left + floor((2 i + 1)(right - left) /
    2 w) at column i; GS Gouraud interpolation on hardware is NOT verified.
  * The GS frame-buffer copy of section 4 and the battle scene behind the windows.
  * Icons 33..47 (slot 5 sheet): none is reachable from these windows (the key glyphs of
    212780 are 19..22, the skill list uses 0..32).
  * The practice-menu owner of the key widget (PauseArt::drawKeyWidget is the same 212478).
  * The scheduler order between the battle thread, the pause task and the child tasks.
