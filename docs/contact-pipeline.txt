SLPS_255.59 — 双角色候选接触队列（2026-11-18）

范围
实现资源 00、两个普通玩家对象的候选接触收集、筛选和排序。
这一步不执行伤害、防御、受击、命中停顿、碰撞挤压、消重标志或音效。
查看器使用固定的普通持武器状态快照（actor+0x23c=0x1000、state flags=0）；
不是从完整战斗状态机产生的演员状态。数字键仍是检查样例选择。
对手朝向固定向左，默认坐标 X=64；不自动转身。左右键每次调整 4 个检查坐标单位，
该步长只是查看器操作，不是原版移动速度。背景、相机和叠放顺序也是检查视图。

原始数据
work/ss6/extract_collision_tables.py 固定校验 ELF SHA-256，再提取 460 字节：
0x4d70e8：36 条通用类型到分类的二字节项，共 72 字节。
0x4d7130：18×18 有向路由表，共 324 字节。
0x4d7278：角色表槽 0 的 32 条二字节项，共 64 字节。
产物 collision_00.bin；地址、长度和散列保存在 collision_tables.json。
不把这些二进制值抄写成自行推测的招式参数；最终原生程序只读取数据，不执行原版代码。
JDG 六位类型中的 41 种在本表有有效分类；未定义项（分类 255）立即拒绝。
不将资源 00 的角色专属表套用到其他角色。

0x153028 — metadata 解码
type=word>>26。
field=(word>>19)&127；quotient=field/6。
group=quotient>>2，variant=quotient&3，remainder=field%6。
另保留 bit18、bits7..17 和 low7。这些字段没有擅自重命名成伤害或硬直。

0x1536e8 — 收集
输入是两个 action object；battle actor 由 object+0x0c 的槽位取出，
global 0x4d3d08 指向 actor 数组，stride=0xf2c。
同 owner（object+0x10）跳过。
0x1539f8 准备描述符：普通玩家的 actor+0x23c bit0x400 禁止参与。
0x153a68 按 ACT JDG 引用依次解码 metadata、分类和世界矩形。
外层遍历 A 的判定，内层遍历 B 的判定，保持原顺序，不先去重。
A+0x104 bit0x00800000、B+0x104 bit0x01000000 会屏蔽当前方向。
0x11e268 的特殊标志检查：普通对象使用 +0x108 bit0x01000000；
A 有标志则跳过，B 有标志则强制路由 10，之后仍要通过该路由筛选。
普通对象之外的特殊类型路径尚未移植，当前 API 不接收它们。

0x153118 查有向路由表，255 表示不进入接触处理。
路由 0 -> 0x153f18；1 -> 0x153cc0；2/3/4/7/8 -> 0x153cd8（2 另有前置筛选）；
5 -> 0x153bf0，普通玩家目标不通过；6 直接允许；9 -> 0x153f58；
10 -> 0x153c48；11 -> 0x153b60，直接允许。
精确的普通玩家筛选见 src/collision.cpp，原始字段名保留以免过早赋予含义。
actor+0x23c bit0x200000 的替代状态查询有额外映射，目前明确拒绝。
其他角色的特殊分支（例如角色 33 的状态 96 豁免）不属于资源 00 实现范围。

路由允许后调用 0x1532d0 的含边界相交；相交才创建事件。
路由 7 的 extra 来自 0x1696c8：actor stateFlags bit4 -> 2，否则 bit2 -> 1，否则 0。
stateFlags 在普通状态位于 actor+0x19a；0x150158 的替代状态路径不在当前范围。
动作 185 的 raw type 10 -> 分类 2，与 idle raw type 1/2/3 -> 分类 5 相遇，路由为 7。
同一个攻击框可以接触多个对方框，候选数不等于命中次数。

0x154028 / 0x1543d8 — 事件和队列
原始事件长 0x6c：
+00 路由；+04/+08 中心；+0c extra；+10 源 JDG auxiliary；+14 交集宽度；+18=0。
+1c 源 ACT judgmentFlags 半字，随后七个解码字段、分类指针、对象指针。
+44 目标 ACT judgmentFlags 半字，随后同样的字段和指针。
两处半字后有未初始化填充，比较时不将填充视为游戏状态。
原生事件用分类值和玩家槽位代替 PS2 内存指针，另保留原始 JDG 索引供检查。
global count=0x12d2698，buffer pointer=0x4d89b8，容量 162。
原版超容量走断言；原生抛出错误，不越界或静默截断。

0x1544a0 — 排序
按路由升序做选择排序，严格小于时更新最小项，交换整个事件。
这不是稳定排序：例如两个相同优先级事件可能因为后来的更小项交换而改变先后。
不能用 stable_sort 替代。原生实现保留交换行为。
双角色查看器以 A->B、B->A 顺序收集，然后排序；它不是完整对象列表调度器。

后续结算边界（消费位基础函数现已移植，下游处理器未实现）
0x154678 排序后调用特殊分派、已消费检查、路由处理器，并写回标志。
0x154a88 查询 object+0x100 中的位；0x154ac0 设置消费位，index 0 还会设置
object+0x104 bit0x02000000，特定标志下另设 bit0x04000000。
标记索引由 0x4d89c0 的每路由二项表指定。它们与实际处理器一起决定重复接触处理。
尚未运行处理器前，不能抢先写这些位或把队列中的路由 7 宣称为成功扣血。
下一步需要沿 0x154678、0x156820 与 0x5eb054 路由分派表移植普通命中/防御路径。

朝向显示
普通 PIL 路径 0x121858 反转 X 偏移；0x121d70..0x121d90 减去图像宽度并 XOR 局部翻转。
在已支持的无效果、固定图层子集中，等价于合成画布水平反射。
200 像素画布的坐标原点从边界 x=90 变为 x=110，而不是像素 109。
不扩展到旋转、染色、特殊比例/效果或其他渲染路径。
