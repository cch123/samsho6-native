1c1f88 (132f5d0 / d4 / d8 = 654e74 / 78 / 7c) and 1c2010 (cloud layers). The opening 1c60c8

  never read), 132f5d4 D picture right, 132f5d8 E picture bottom, 132f5dc / e0 arrival offset.

  654dd8[4..6], 654db0[5..9]); per sprite x, speed, height and an ease step; per layer y and
  ease step; 132f6fc "opened".

2. Path / arrival / cloud easing
--------------------------------
All four easing routines evaluate s = sin(quarter - step*pi/steps*half) in EE single precision
for the argument, widened by 310be0, through the C library sine 30bd00 (its 60 results are
captured from the original and pinned in arcade_map.bin), then target - span*s through the
fp-bit double routines 310fa0 / 310f38 (truncating to 53 bits) and 311510.
CORRECTION / precision rule: 311510 (truncdfsf2) TRUNCATES toward zero (2000 random doubles
in Probe), it does not round to nearest.
1c3608 path (step 582384, 60 steps): A = 94 - 94s, B = 90 - 90s, C = 0.758 - (-0.242)s,
  D = 697 - 57s, E = 434 - (-46)s (the immediates are built with lui/ori/dsll32 in the code).
1c3888 arrival (step 58238c, 60 steps): offset x/y = t - t*s with t from 6550b0 / 6550e0
  indexed by G.stage; C = step*655120/655114 + 655124 (single precision); D = 1280 - 583s,
  E = 960 - 526s.
1c3b78 open (skipped once 132f6fc is set): layer y via 1c4118 toward 655128..655144, cloud
  heights via 1c4230 to h*65512c; 132f6fc = 1 and all steps cleared when all 17 complete.
1c3ec8 close: same with 655148..655164 / h*65514c -> h, no completion flag.

5. Walk-in 1c4428 (coroutine 1c4568, redraw task 1c43f0)
-------------------------------------------------------
Matches flow spec 5.3, with:
- Task order per frame: 1c43f0 (priority 0xa: 1c2860, 1c2920, 1c31f0, 1c3260, 1c2a38 — clouds
  keep moving; the path/arrival state is frozen at its final value) then the coroutine.
- Objects tag 0x1772: seat 0 at x 0xf0 (action 0x703 iff mode 1 and P[0].+14 == 0, else 0x704),
  seat 1 at x 0x190 flags 0x80000 (0x703 iff mode 2 and P[1].+14 == 0). A fighter that starts
  in 0x703 counts as already finished; the other seat gets the 0x1e-frame start delay. Every
  finished action (0x704 included) is restarted as the loop 0x703.
- 10add8(0x10000..0x10002, 0x10) returns without a write (ids above 0x1ff).
- Phase A: the first visit always runs; then while the countdown (0x3c) is positive. Any
  pressed & 0x60f zeroes it.
- Phase B: the 58244c wait counts only after both objects have finished; pressed & 0x60f sets
  it to the limit.
- Pair message 1a3168(listener, speaker): table 50d550 (byte 43d052 == 0, 49 characters) or
  50d618 (43 characters); entry +4: two generic list pointers, then 51 pair pointers by
  listener. A null pair entry draws one 316b90 value: generic[(r >> 14) & 1]. The speaker is
  the CPU; in mode 2 the balloon id gets +5 (mirrored balloon: u + w with negative width).
- 1a26b0 (balloon rows 4eeef8 {slot, x, y, u, v, w, h, text x, text y}, z 60a080): balloon
  sprite, then up to three lines through 113028 with colour -1 at 24-pixel rows starting at
  y + text y + (3 - lines) * 14; every glyph counts against 3d3aa0 (= frame / 4). It returns
  "done" when the glyphs drawn are fewer than the limit. With 3ec73c set 1130f8 / 1131d8
  neither draw nor count (the walk-in then sees done as soon as the limit is positive).
- Text fast-forward: frame = 0x2710; second press: n = 0. The hold loop draws the balloon
  with limit 0 (no text).
- START hold (582444 / 582448) toggles in the dialogue wait and in the final loop, exactly as
  the flow spec states; exits 1252f0(2, 0, 1c44f0, 1c5290) / 1252f0(2, 0, 1c44f0, 139760), once
  (latch 582440). The final-loop exit happens on the visit AFTER the hold loop is first entered.
- Intruder: 1c2420 sets 5823ac = 17a548() (and on 1 forces G.stage 3 / CPU character 33); the
  walk-in skips the dialogue when 5823ac == 1. The kind-4 banner entry 1252f0(4, 1, …, 1c1b20)
  belongs to the callers (stage dialogue 1c53e0 / win quote 136288), not to the map.
- 1c44f0: frees 0x1771 / 0x1772 / 0x1b5e, 1e7ad0, 1e7b40.
