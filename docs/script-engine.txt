Common per-actor move-script interpreter (163570..1655ff)
=========================================================

Scope: static reverse engineering of the pinned ELF work/ss6/extracted/SLPS_255.59
(MIPS R5900, little endian). Every statement below was read from the disassembly
(analyze_elf.py) unless it is marked INFERRED (meaning assigned from usage) or
UNVERIFIED (not confirmed). No runtime trace of these functions has been compared
yet; nothing here is "runtime-verified". Delay slots have been accounted for.

Glossary
  ACT     per-character action (animation) record bank; an "ACT id" is an action
          number queued through 1493c0/1494c0.
  row     one 20-byte record of table A (4e2788[character]).
  script  a run of rows starting at a row whose byte+0 equals the script id;
          following rows normally carry id 0xff ("continuation rows").
  cb      the callback argument passed to actor callbacks: cb[0] = actor,
          cb[1] = opponent actor (INFERRED from usage: cb[1][0] is used as a body,
          cb[1]+0x194/+0x244/+0xa10 as actor fields).
  actor   the fighter controller structure (native StateEntryActor and bases).
  body    *(actor+0), the fighter's ordinary object (native PlayerObject).
  aux     *(actor+4), the separate auxiliary object (Nakoruru eagle, Rimururu
          Konru, Mina's companion, ...; native SelectionActor::auxiliaryState128 is
          aux+0x128). Not to be confused with the opponent.
  opp     cb[1] (opponent actor); opp body = *(opp+0).
  RNG     the game's library random generator 112300(bound) (native GameRandom).
  EE      Emotion Engine; EE cvt.w.s always truncates toward zero.
  feature n
          word actor+0x2c4+4*n, i.e. native ActorCommandInput::sampledFeatures[n]
          (layout confirmed by state_transition_probe.cpp, which maps feature i to
          actor offset 0x2c4+4*i).

  f6  (+0x2dc, owner+0x18)  fresh (unlatched) press of button 0
  f7  (+0x2e0, owner+0x1c)  fresh press of button 1

1. Registry: actor+0x28c .. actor+0x2bf (13 words, native registry28c)
---------------------------------------------------------------------
  r[0]  +0x00 (actor+0x28c) current row index, relative to r[11]
  r[1]  +0x04 (actor+0x290) index of the row whose entry has been applied.
        164460 enters a row iff r[0] != r[1]. -1 after 163488.
  r[2]  +0x08 (actor+0x294) pending override ACT id, -1 = none. Written by the
        per-visit branch logic (1638e8) and entry events; any value != -1 makes
        164600 report the row complete, and the next row entry queues r[2]
        instead of the row ACT.
  r[3]  +0x0c (actor+0x298) variant ("strength" 0..2 in the ports). Passed by the
        caller of 163590; also copied to actor+0x26c (callbacks260[3]).
  r[4]  +0x10, r[5] +0x14  not touched by this engine except 163450 clearing
        (hanzo_capture.cpp uses them for capture motion values).
  r[6]  +0x18 (actor+0x2a4) "was airborne": (0.0 < body.y) captured at every row
        entry and refreshed on most not-complete visits (164738).
  r[7..9] +0x1c..+0x24  cleared only by 1634e8 (table-B engine), unused here.
  r[10] +0x28 (actor+0x2b4) linked object reference; not touched here except
        163450 clearing (14a348 flags it first; see state_transition.cpp:125).
  r[11] +0x2c (actor+0x2b8) table-A row base of the running script (0 = none).
        Also read by the projectile spawner 16d9c8 (section 9).
  r[12] +0x30 (actor+0x2bc) table-B row base (1634e8 engine only).

163450(reg)  "release": memset(reg,0,0x34) [315f38]; reg[2] = -1.
             Callers: 148ddc, 14a75c (state entry), 16381c (script end),
             166bd4, 168900.
163488(reg, character, scriptId, variant)  -> bool
             row = 163348(character, scriptId); reg[11] = row (ALWAYS written,
             0 when not found);
             if row: reg[2] = -1; reg[3] = variant; reg[0] = 0; reg[1] = -1;
             return row != 0.  r[4..10], r[12] are NOT cleared.
1634e8(reg, character, scriptId, variant)  -> bool   (table-B twin)
             row = 1633c0(character, scriptId); reg[12] = row;
             if row: reg[3] = variant; reg[2] = -1; reg[0] = 0; reg[1] = -1;
                     reg[7] = reg[8] = reg[9] = 0;
             Callers 165abc, 168914 (outside this engine).

2. Table lookup
---------------
163348(character, id)  table A, pointer table 0x4e2788 (51 entries, [51]=0):
    p = word[0x4e2788 + 4*character]; for i in 0..0xfff:
        if p[20*i+0] == id: return p + 20*i
        if p[20*i+4] == 0xff: return 0      // terminator = END CODE 0xff, not id
    return 0
  Note the terminator test is on byte+4 of the row being scanned, after its id
  compare; the terminator row of every character is
  ff 00 ffff ff 00 ffff ffff ffff 00 ff ffff 12 00 00 ff.
1633c0(character, id)  table B, pointer table 0x4e4a68:
    same loop, but terminates when byte+0 == 0xff (checked after the id compare).
163430(id) -> 0x4e4b38 + 12*id   projectile descriptor record (12 bytes), used by
    16d2b0/16dcc0 and others (153ba4, 153c28, 16176c, 16d360, 16d954, 16de9c,
    16df24). Rimururu port documents 4e4b38[2..10].
163570(selector) -> script id: (selector == 0xff || selector < 0x80 signed)
    ? -1 : selector - 0x80. 51 callers, all in character code 1ec1ec..20bd6c.

3. Row layout (20 bytes, table A)
---------------------------------
  +0x00 u8   script id (lookup key); 0xff on continuation rows. 164460 also
             reads it for character 23 (section 6).
  +0x01 u8   0 in every row of every character; not read by this engine.
  +0x02 s16  ACT id queued at row entry; -1 = keep the running ACT. Also the
             expected ACT for type-4 verification (163610).
  +0x04 u8   end code 0..13 (164600 jump table, section 7). 0xff = table
             terminator. 163610 additionally tests byte+4 == 1 at script end.
  +0x05 u8   0 everywhere; not read.
  +0x06 s16  branch target A: override ACT taken when body.104 & 0x40000.
             Also the target of type 0x3c/0x3d/0x3e button logic.
  +0x08 s16  branch target B: taken when body.104 & 0x80000.
  +0x0a s16  branch target C: taken when 14aad8 reports the facing camera edge.
  +0x0c u8   flags:
             0x01 last row of the script (163610)
             0x02 ACT += variant (164460, type-4 check, 1638e8 offset)
             0x04 armed/unarmed pair: ACT += 2*variant, +1 more when unarmed
                  (actor.23c & 0x1000 == 0). Tested BEFORE 0x02.
             0x08 face the opponent on entry: 14a978(actor,0)
             0x10 never read by this engine (UNVERIFIED external use)
             0x20 apply the variant offset to branch A
             0x40 apply the variant offset to branch B
             0x80 apply the variant offset to branch C
  +0x0d u8   projectile spawn mode (0, 2, 3, 4 or 0xff), read by 16d9c8 only.
  +0x0e s16  projectile descriptor id (-1 when unused), read by 16d9c8 only.
  +0x10 u8, +0x11 u8, +0x12 u8   not read by any table-A reader found
             (163610 family or 16d9c8). Observed value sets over all
             characters: +0x10 {3..8}, +0x11 {0,1,2,4,5,0x43},
             +0x12 {0,1,2,4,5,7,14}; terminator has 0x12,0,0. Meaning UNVERIFIED.
  +0x13 u8   row type (event code). 0xff on most rows = no event.

A scan of .text for any `addiu rX,rY,0x28c` followed by `lw ...,0x2c(rX)` and for
`lw ...,0x2b8(...)` finds only 163644 and 16da30; table A rows are therefore read
only by this engine and 16d9c8 (registry pointers passed as arguments elsewhere
are not excluded by this scan; UNVERIFIED completeness).

4. Entry: 163590(cb, scriptId, variant)
---------------------------------------
    actor = cb[0]; reg = actor+0x28c
    163488(reg, actor.a10 /*character*/, scriptId, variant)
    actor.26c = variant                    // callbacks260[3], even if not found
    164460(reg, cb)                        // enters row 0 (r[0]=0 != r[1]=-1)
    1522a0(actor+0x260, 0x163610, 1, -1)   // tail call
1522a0(p, pc, a, b): p[2] = b; p[0] = pc; p[1] = a (three words only).
Ordering facts: the row-0 entry event and its ACT queue run BEFORE the callback is
bound, so any callbacks260[0..2] written by the row-0 entry are overwritten.
If the script is not found, r[11] = 0 and 164460 runs with stale r[0]/r[1]; if
they differ it dereferences 20*r[0] from address 0 (UNVERIFIED; no caller is
known to pass a missing id).

5. Per-visit step: 163610(cb)   (the bound callback)
----------------------------------------------------
    actor = cb[0]; reg = actor+0x28c
    row0 = reg[11] + 20*reg[0]          // OLD row, captured before anything runs
    advance = 1
    1638e8(reg, cb)                      // section 8: per-visit row effects
    if (164600(reg, cb) == 0) goto tail  // section 7: row complete?
    type = row0[0x13]                    // read from the OLD row pointer
    if (type == 0x2a && (actor.244 & 0x04000000)) {
        14ff80(actor+0x18c, 1, 0x4d)     // pendingTable=1, pendingIndex=0x4d
        actor.18c = 1
        return                           // NO 164460, no registry change
    }
    if (type == 0x10 && (actor.f1f & 1) && (actor.f1c & 0x06000000) == 0x06000000)
        1e8298(actor.a24, 0xc7, actor.a10)   // sound request; i.e. f1f&7 == 7
    if (type == 4) {                     // ACT verification
        cur = reg[11] + 20*reg[0]        // FRESH index
        f = cur[0xc]
        expect = (s16)row0[2]
        if (f & 2)        expect += reg[3]
        else if (f & 4)   expect += 2*reg[3] + ((actor.23c & 0x1000) ? 0 : 1)
        // note: here 0x02 is tested before 0x04 (opposite of 164460)
        if (body.24 != expect) { advance = 0; reg[1] = reg[0] - 1 }
    }
    if (!advance) goto tail              // forces re-entry of the same row
    cur = reg[11] + 20*reg[0]            // FRESH
    if (!(cur[0xc] & 1)) { reg[0] = reg[0] + 1; goto tail }
    if (reg[2] != -1)    { reg[0] = reg[0] + 1; goto tail }   // override pending
    // ---- script end (last row completed with no override) ----
    if (row0[4] == 1 && !(body.y > 0.0f)) {        // c.ole.s y,0 => y <= 0
        1697d0(cb)                     // 11d990 stop; if y < 0 then y = 0
        1494c0(actor, 0x24e, 0x24f, 0) // armed 590 / unarmed 591, not forced
        1522a0(actor+0x260, 0x169a50, 1, -1); actor.274 = 0   // 169a50 mode 0
        163450(reg); return
    }
    switch (row0[0x13]) {              // byte4 != 1, or byte4 == 1 and y > 0 (or NaN)
      case 9:  14ff80(actor+0x18c, 0, 0x20); break
      case 10: 14ff80(actor+0x18c, 0, 0x21); break
      case 11: 14ff80(actor+0x18c, 0, 0x22); break
      default: 169918(cb)              // standard recovery, see below
    }
    163450(reg); return
  tail:
    164460(reg, cb)                    // tail call: enter row if r[0] != r[1]

169918(cb): actor.23c = f63 ? (23c | 8) : (23c & ~8); tail 169810 (common
recovery; native knockdown.hpp recoverStanding / ground_state.cpp:264).
Important consequences:
  - Row advance, the new row's entry event and its ACT queue all happen in the
    SAME visit as the completion.
  - Type 4 only acts on a completed row. A mismatch rewinds r[1], so the same
    row re-enters (re-queues its ACT, or r[2] if one is pending, re-runs its
    entry event, resets body.134 and r[6]).
  - If 1638e8 incremented r[0] (types 0x30/0x31), row0 is still the old row
    while "cur" is the new one, so the old row's type and byte+4 are used.
  - 1494c0(actor, armedAct, unarmedAct, force) -> 1493c0(actor, (actor.23c &
    0x1000) ? armedAct : unarmedAct, force). 1493c0 = native queue of
    actor.a3c (PlayerObject::markActorActionPending / GroundStateRuntime);
    force != 0 also sets a3c=-1, body.c0=0, body.104|=1 first. It clears
    actor.248 bit 0x800 and applies the 168c18 lock table (ports' lockTicks).

Ordering: facing (row flag 8) -> character-23 forced facing -> entry event ->
ACT queue -> registry bookkeeping. The entry event therefore sees the OLD r[2],
r[1] and body.134; any r[2] written by the event itself (types 0x1b, 0x24, 0x33,
0x35, 0x3a) is consumed immediately by the queue step of the same entry.
14a978(actor, force): face the opponent (native: action_selection; equal X keeps
facing; force=0 respects actor.23c & 0x10 and the 1500a8/1500d0 alias gates).
