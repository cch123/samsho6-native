Arcade overlay, Continue and Game Over drawing (SLPS-25559)
==========================================================

Scope: the draw routines of the arcade score digits (1bc098), the free-seat legend (1ba1b0),
the state-9 tally (1c8a98 and the 113028 texts of 1c7f08), Continue (137d20) and Game Over
(138af0). Logic is in docs/mode-arcade-tally.txt and docs/mode-arcade-flow.txt; where this file
disagrees with their drawing notes, this file wins (section 9).

Evidence classes
  OBSERVED   read from the disassembly; [V] = compared with the original routine executed in
             Probe by work/ss6/validate_arcade_art.py (outputs/ss6-feasibility/
             arcade_art_validation.json): identical submission-queue entries (exact float bits)
             and identical 640x480 frames under the reference painter of validate_menu_canvas.py.
  INFERRED   deduced from use; not executed.
  UNKNOWN    not read.
Native port: src/arcade_art.hpp/.cpp. Tables: work/ss6/extract_arcade_art.py -> arcade_art.bin
(700 bytes), manifest outputs/ss6-feasibility/arcade_art_tables.json; the tally, score and
legend layout words come from arcade_tally.bin.

3  Free-seat legend (OBSERVED [V])
----------------------------------

1ba1b0: runs only when word 582208 != 0. mode == 0 -> 1ba228; else sub-mode != 5 -> 1ba448.
The blink clock 1ba148 advances once per call of 1ba228 / 1ba448 and nothing is drawn while it
returns 0. Every piece: 3db8fc = 1, 3db900 = -1, 1b8e28 (slot 0x28) at depth -600.
1ba448, seat s drawn for s == 1 in mode 1 and s == 0 in mode 2:
    gameData+0x2c == 1 || gameData+0x30 == 1: 4c3f10[0] (1,105,124,12) at (0x10,0x10) /
        (0x1e1,0x10)
    otherwise: 1b9880 submits 4c3ec8[0] once at the seat position (0x10,0x10) / (0x1b0,0x10),
        then the loop submits 4c3ec8[0..2] = (1,66,64,12) (60,92,64,12) (1,79,73,12) from the
        same x, advancing by each width. The first piece is therefore submitted twice.
    The branch between "draw" and "skip" tests two stack bytes that the empty hooks 110ae8 /
    110af0 never write. Probe's zeroed stack selects "draw"; the residue on the console
    stack is UNKNOWN.
1ba228 (mode 0): latched -> 4c3f10[0] at (0xf9,0x140); otherwise the three pieces from
    (0xe0,0x140) (no duplicate).
Mode 3 and others draw nothing but still advance the clock (sub-mode != 5).

7  Cubic 1382a8 / 138eb0 (OBSERVED [V], whole functions)
--------------------------------------------------------

f(step a0, P0 a1, P3 a2, P1 a3, P2 t0, total t1), constants 1.0 and 3.0 (5e163c / 5e1640 and
5e191c / 5e1920):
    t = step / total; s = 1 - t
    ACC  = s*s*s * P0                (MULA.S)
    ACC += ((3s)*s)*t * P1           (MADDA.S)
    ACC += (((3s)*t)*t) * P2         (MADDA.S)
    result = trunc(ACC + (t*t*t) * P3)   (MADD.S)
with the multiplication order of the listing. Each product and each accumulation is rounded
separately in the project's finite float model (Probe and ScalarFloat agree; not a hardware
claim).


8  UNKNOWN / not done
---------------------

  - The loser object and the stage background are described as a request
    (ArcadeFighterRequest) and are not rendered or compared by this slice.
  - GS coverage of the turned panel edges: both sides use the inverse-affine pixel-centre
    model of validate_menu_canvas.py.
  - 114f20 was not read (section 1). Writers of 3d3aa8 / 3d2e50 outside the graphics module
    (debug read-outs of 1132c0) were not searched.
  - The stack bytes tested by 1ba448 (section 3).
  - 1170d8 / 117170 fade progression is the caller's; this module only accepts the resulting
    3ebf18 / 3ec734 / 3ec730 state (MenuCanvas::setFade + ArcadeArt::setFade).
  - Completed fade (3ec73c != 0): 1149d0 and 1130f8 submit nothing except slot 0x28. The
    caller must skip every overlay but the legend in that state; not modelled in the draw
    functions.


9  Corrections to earlier documents
-----------------------------------

  - docs/mode-arcade-tally.txt section 7: the legend is submitted through sheet slot 0x28
    (1b8e28 overrides the record's slot word 27), not "texture slot 27".
  - docs/mode-arcade-tally.txt section 6: a negative score is not an UNKNOWN picture: the
    records in front of 4c5ae8 are listed in section 2 above.
  - docs/mode-arcade-tally.txt section 5: 113028 draws 12x24 half-width glyphs at depth
    114e40(3d3aac) = -200, black (colour argument 0xff000000 = alpha ff, RGB 0).
  - docs/mode-arcade-flow.txt 5.9: the scaled digit variant is selected by R % 60 < 0x15
    (21 frames); src/arcade_run.hpp's comment "phase < 15" is hexadecimal.
