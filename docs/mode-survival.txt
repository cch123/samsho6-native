SURVIVAL MODE (SLPS-25559) -- static specification
====================================================

Scope: mode-menu item 3 (SURVIVAL), the unlock rule of the SURVIVAL / GALLERY / SPIRITS
EDIT menu rows, character-select differences, opponent candidate generation, the
in-battle survival controller (candidate selection, bonus conditions, rewards, in-place
opponent replacement), every battle-side branch on the survival predicate, the end of
a run, the per-character record and its location in the save image, and exit paths.
Source: static reading of work/ss6/extracted/SLPS_255.59. No Probe (work/ss6/mips_probe.py
interpreter) run was used. All addresses are hexadecimal EE virtual addresses; for
.data and .rodata the file offset is (address - 0xff000).
Labels:
  OBSERVED  = read directly from instructions/data at the cited address.
  INFERRED  = interpretation of observed code; not proven by execution.
  UNKNOWN   = not read / not resolved.
Related documents (not repeated here): docs/mode-practice.txt (shared battle-scene loop
138f48, predicates 139388/1393a0/139430), docs/mode-arcade-flow.txt (Game Over scene
138340, unlock announcement 1e5d88), docs/mode-gallery.txt A.4.6 (unlock predicate
table 584f78), docs/mode-option.txt.

1. OVERVIEW
-----------

Survival is ONE battle scene that is never left between opponents. The human fights a
sequence of up to 49 single-round matches. Before every match (including the first) a
three-row candidate window is shown; each candidate fixes the opponent character, the
stage, the opponent colour, the SPIRIT THE HUMAN MUST USE, a bonus condition ("mission")
and a reward. Life and the round clock carry over between opponents; rewards restore
life and/or clock. A time-up always counts as a loss. The run ends on the first loss or
after the 49th win; the Game Over scene 138340 then stores the per-character record
(wins, elapsed seconds).
