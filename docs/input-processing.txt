Original input processing (SLPS_255.59)
=====================================

This is a native input subsystem, not an emulator dependency. The bounded
instruction runner is used only by offline validation scripts. The current
battle.command still sends direct TrialCommand state requests: recognition
is not yet connected to original action selection/permission/cancel logic.
Do not describe the current playable fixture as having full original inputs.

Sampling compatibility details
------------------------------
118128 returns1237cc8+12*player. +0/+4 supply held/edge words to177310;
the physical pad driver and SDL keyboard/controller adapter remain separate.
Normalized direction bits4..7 and start-like bit3 are fixed at this boundary;
eight masks come from4eaac0+32*player, or12d32d8 in game mode6.
Masks test any intersection. Three combination inputs expand buttons1+2,
0+1 and0+3 after recording the original13 input bits.

Both600-halfword recording arrays (12d2978 held,12d2e28 edges) are shared.
Unsigned index<600 means negative indices are rejected too. Out-of-range
playback yields neutral input; out-of-range live input skips recording.
Playback ignores current pad words and current mappings, then applies the
current facing/reversal and combination-button expansion.

First and second facing are independently XORed with direction reversal.
149634..149730 supplies actor+a08 and body+38 bit19. Direction reversal is
actor+200>0 (timer20), NOT body height. The exact gameplay cause of timer20
is not named here until its producers are ported.

171 words live at12d26b8. Sampling preserves offsetc0, which is not written.
There are three direction blocks: expected-facing, actual-facing, and world
directions. Only one diagonal pair is resolved per block, in original order;
opposing held directions are not neutralized. Do not add modern SOCD rules.

Raw edges, exclusive edges and four-visit latched edges are separate.
Any other held button suppresses an exclusive edge. Each new edge sets its
player's latch to4; absent edges decrement nonzero latches before publishing.
Pair/triple predicates use latched edges, while direction+button predicates
mostly use raw edges. The shipped0x9c triple repeats024, not034; preserved.

Recognition compatibility details
---------------------------------
Each template has14 tokens, timeout, completion-buffer duration and optional
reset predicate.255 terminates,48 is the charge marker. At a noninitial step
the8-bit elapsed counter increments/wraps BEFORE timeout comparison.
Failure/reset clears step/elapsed/charge, preserving an existing match buffer.
Only direction-token49..101 followed by button-token6..45 can coalesce in
one call. Other tokens consume separate visits.

Charge requires52 held visits AFTER entering the marker; its counter caps at
6000. Releasing with charge>=52 can immediately consume the next direction
and button within that same visit.178dc8 maps button0..4 to held91..95 and
accepts only its original direction classes, not arbitrary features.

178980 substitutes feature49..65 from66..82 for alternate-facing bindings,
then restores the shared frame. Native recognition uses a nonmutating view.
179530 publishes immediate match OR the old completion buffer, then ages
all31+32 buffers if requested, including unused special slots. A disabled
definition(-1) can still publish a preexisting completion buffer. Special
cancel-permission flags (owner+3a8, previously mislabeled consumed) are
cleared only for the visited special slots. See input-permissions.txt.

Bindings and order
------------------
179178 clears actor predicates/results/progress/definitions, but preserves
alternate-direction flags and priority bytes. Null179258 config disables the
owner without clearing those preserved fields.
Per-character override halfwords replace normal slots23,2,3,8. Individual
system6 descriptor fields choose availability columns independently. The
special category checks use168d48/168dc8, including explicit character32/48
extra cases. Eligible alternate special commands consume override halfwords
4/5 only as those category slots are encountered; unavailable slots do not
advance that replacement cursor.
Priority order begins with reversed slot indices, then selection-sorts by
descending priority byte. Strict comparison, unstable ties and inclusion of
disabled definitions are all retained; do not replace with stable_sort.
