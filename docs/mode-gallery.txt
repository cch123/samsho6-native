GALLERY MODE (menu item 6) AND SHARED MENU INFRASTRUCTURE -- SLPS-25559
========================================================================
Static reverse-engineering specification. Source: work/ss6/extracted/SLPS_255.59
(.text 0x100000..0x32cd70, .data 0x32ce00..0x5d3744, .rodata 0x5d3c00..0x67bc84,
.bss from 0x67bd80). Nothing here was executed unless a paragraph says so.

Labels: OBSERVED = read from instructions/data at the cited address.
        INFERRED = interpretation of observed code.  UNKNOWN = not resolved.

Document layout
  PART A    gallery scenes (top menu, ending viewer, sound test, illustration viewer),
            unlock storage, interaction with battle code
  PART A.W  widget library used by the three gallery sub-scenes (list widget,
            sliding panel, message window, sound/BGM calls)
  PART B    infrastructure shared by all non-battle menus (scene transition, quad
            submit, text, pad structure, menu background, help ticker)

Glossary
  seat      pad/port index 0 or 1 (P1/P2)
  GS        Graphics Synthesizer (PS2 rasteriser)
  SJIS      Shift_JIS text encoding
  W / P / M list widget / sliding panel embedded in W at W+0x1c / message window
            (all specified in PART A.W)


PART A -- GALLERY
=================

A.0 Summary
-----------
The gallery is NOT an image-thumbnail browser. It is a four-row text menu
(scene 0x1d22f8) that leads to three independent sub-scenes:

  row 0  エンディング鑑賞  ending viewer      scene 0x182968 (shared with the arcade ending)
  row 1  ＢＧＭ鑑賞        sound test         scene 0x13e090 (BGM / voice+SE / narration)
  row 2  イラスト鑑賞      illustration viewer scene 0x13ed98 (55 images gl_00..gl_54)
  row 3  EXIT              back to title/mode menu scene 0x127940

    mode menu 0x1ccfd0 item 6
          | mode word 0x4c3808 = 0xd (P1) / 0xe (P2); 1d2610(): [0x582d88]=0
          v
   +--------------------+  cancel / row 3   +---------------------------+
   | gallery top menu   |------------------>| title + mode menu 0x127940|
   | 0x1d22f8 task 1d2380|                  +---------------------------+
   +--------------------+
      | row 0        | row 1            | row 2
      v              v                  v
  +-----------+  +--------------+  +------------------+
  | 0x182968  |  | 0x13e090     |  | 0x13ed98         |
  | ending    |  | sound test   |  | illustration     |
  | select +  |  | task 13e0e8  |  | viewer task      |
  | playback  |  |              |  | 13edf0           |
  +-----------+  +--------------+  +------------------+
      | cancel       | cancel           | cancel
      +--------------+------------------+----> 0x1d22f8 (row cursor preserved)

There is no movie player and no per-thumbnail page navigation. There is no
gallery viewer that runs fighter actions; the battle sound special case for
modes 13/14 exists because the sound test replays battle voice/SE command
numbers through the battle sound entry 0x1e8298 (section A.7).


A.1 Entry from the mode menu and exit paths
-------------------------------------------
OBSERVED (brief + 0x1d2610): mode-menu item 6 writes mode word 0x4c3808 = 0xd/0xe,
0x4c38a8 = 0, calls 0x1d2610 ([0x582d88] = 0, the top-menu row cursor) and
requests scene 0x1d22f8.

Scene entry 0x1d22f8 (OBSERVED, in call order):
  112670(priority 0x14, handler 0x1d2380, 0x10, tag 0x1783)
  118320(0x1d24f0)            register scene destructor
  1ce478()                    shared menu-background setup (PART B)
  1d2370()                    [0x582d8c] = 0   (exit-requested latch)
  s = 1d28d0([0x582d88])      = [0x582d90 + 8*row].text
  1cebb0(1ceb90(s))           install help-ticker string (PART B)
  112f30(0x00ffffff, 0x00404040)
  tail call 1e7b40()
Destructor 0x1d24f0: 112a70(0x1783).

Exit paths of the top menu:
  cancel, or confirm on row 3 -> 0x1d2508:
        124d50(); 1252f0(1, 0, 0x1d24f0, 0x127940); [0x582d8c] = 1
        (124d50 clears the whole g_GameData block, so the mode word becomes 0 here)
        (0x127940 is the title/mode-menu scene already ported in console_title.*)
  confirm on row 0 -> 1252f0(1, 0, 0x1d24f0, 0x182968); [0x582d8c] = 1
  confirm on row 1 -> 1252f0(1, 0, 0x1d24f0, 0x13e090); [0x582d8c] = 1
  confirm on row 2 -> 1252f0(1, 0, 0x1d24f0, 0x13ed98); [0x582d8c] = 1
  After every confirm (all four rows): 178f70(seat): [0x12d35c4] = (seat==1) ? 1 : 0.
The mode word is not changed by any gallery scene. Each sub-scene returns with
1252f0(1, 0, <its destructor>, 0x1d22f8); the row cursor [0x582d88] is preserved.

Operating seat (OBSERVED 0x178f90, "active seat" getter used by all sub-scenes):
  mode 3            -> ([0x582f3c] == 1)            (0x1da838)
  mode 13 or 14     -> [0x12d35c4]                  (seat that confirmed in the top menu)
  mode 2,5,8,10,12,16 -> 1
  otherwise         -> (mode == 0x12)
Consequence: in the top menu BOTH pads are polled; in a sub-scene only the pad
that pressed confirm in the top menu is polled, independent of whether the mode
word is 0xd or 0xe.

  pad = 118128(seat); pressed = pad[+4]; repeat = pad[+8]
  v = (pressed & 0x404) ? 8 : 0          cancel
  if (pressed & 0x20a) v |= 4            confirm
  if (repeat & 0x10)   v |= 1            up
  if (repeat & 0x20)   v |= 2            down

Per update (one task visit), in instruction order:

  for seat in 0, 1:                                  # 0x1d2398 loop, s0 = seat
      v = 0
      if 1cf750() != 0:                              # menu background/fade ready (PART B)
          if [0x582d8c] == 0: v = 1d28e8(seat)
      if v & 1:        row = (row + 3) mod 4         # 0x1d23cc, C signed remainder
      elif v & 2:      row = (row + 1) mod 4         # 0x1d2484
      elif v & 0x18:   1d2508()                      # cancel (bit 8); bit 0x10 never set
                       1e7b70(-1, 0x25); continue

                       1e7b70(-1, 0); continue
      else:            continue

      [0x582d88] = row

      1e7b70(-1, 0x20)

  1ce660(0, 0, 0)

  1d2620(a)                                          # title sprite
  1d26d0(row, a)                                     # four labels
  1d27c8(row, a)                                     # help ticker        (tail call)

  Up then down by the two seats in one update both apply and both play sound 0x20.

A.7 Interaction with battle code
--------------------------------
Complete scan of .text for `addiu r, r, -0xd` followed within five instructions by
`sltiu r, r, 2` gives eight sites; six test the mode word:
  0x178fa8  active-seat getter (A.1)
  0x18299c  ending scene entry: choose task 0x182ce0 vs 0x182d30 (A.4.1)
  0x182c3c  ending playback epilogue: menu background + [0x4eefd4] (A.4.4)
  0x1a2250  ending abort input: cancel buttons instead of START (A.4.4)
  0x1e8314  battle sound entry 0x1e8298 (below)
  (0x14c978/0x14c988 and 0x1731d4 match the pattern but operate on a slot number
   in s1, not the mode word; they are unrelated.)

0x1e8298(a0, command, a2) (the function ported as SoundSelection::act):
      id = command & 0xfff; actor = 140090(); picked = 1e83c0(id)
      if picked == 0 || picked == 0x103: return 0
      if picked != -1: id = picked
      if mode not in {13,14} && actor != NULL && (actor[+0x23c] & 0x80)
             && 0xaa <= id < 0xc6: return 0
      id >= 0x12c: 1e7b70(a0, id - 0x12c)
      id >= 0x104: 1e7d60(a2, id - 0x104)       # character voice, a2 = character
      id >= 0xaa:  1e7b70(a0, id - 0xaa)
      id >= 0x64:  1e7b70(a0, id - 0x64)
      else:        1e7b70(-1, id - 1)
  Why modes 13/14 are special-cased: the sound test calls this function directly
  (A.5.5, cat 1) with a0 = 0 and the raw command ids stored in the lists at
  0x4cef58/0x4cf360 (170..218, 261..272). No fighter exists in the gallery, so
  140090() returns whatever actor pointer is current (stale or NULL); the mode test
  bypasses the "actor flag 0x80 mutes weapon sounds 170..197" rule so that every
  listed command is audible. src/sound_selection.cpp line ~115 already reproduces the
  condition; a native sound test must call act() with gameMode 13/14, seat 0,
  character = `ch` (or 0 for the common list) and must have loaded the sample banks
  selected by 1e79c8(0, ch) and 1e79c8(1, 0x33/0x34) first (PART A.W).
  Random selection inside 1e83c0 (shared anti-repeat state, GameRandom draws) still
  applies to commands that have a selection record: the sound test consumes the
  shared RNG exactly like battle code does.

No other battle/round/match function branches on modes 13/14. The gallery never
enters the battle dispatcher (0x4c38a8 = 0).

PART A.W — WIDGET LIBRARY USED BY THE GALLERY SUB-SCENES
========================================================

Callers: sound-test task 0x13e0e8, illustration task 0x13edf0, ending-select
0x13f4a8. Everything below was read statically from SLPS_255.59 unless marked
INFERRED or UNKNOWN. All coordinates are integer screen pixels in the 640x448
frame. "seat()" means 0x178f90() (in game modes 13/14 it returns the word
0x12d35c4 written by 0x178f70: 0 = P1 opened the gallery, 1 = P2).

Layering overview

  per frame (caller order):
    17c210()                       reset depth cursor
    1825b8(G)                      tick guide-window panels
    r = 20ee70(Wn, seat)  (xN)     tick list panels + read pad
    ... caller state machine ...
    182600(G)                      draw backdrop, title bar, message bar, key bar
    20ef38(Wn)            (xN)     draw lists
    112a28(0)                      yield

W.1 Depth cursor (0x17c210 / 0x17c228 / 0x17c250)
-------------------------------------------------
  0x4ee54c  float zBase      (17c250(f12) stores it; 17c210 clears it to 0.0)
  0x12d3850 float zCursor    (17c210 clears it to 0.0)
  17c228(f12 = z): returns z - zCursor, then zCursor += 0.1 (constant 0x5f1f08).
Every primitive of this library calls 17c228(zBase - K) for its Z, with K a
per-primitive constant (500, 700, 800, 900, 1000 below). Consequence
(OBSERVED arithmetic, INFERRED meaning): larger K is nearer the viewer, and
within one K later submissions are 0.1 nearer than earlier ones.
Primitives: 1145c0(a0=x, a1=y, a2=w, a3=h, t0=colour32; f12=z) flat rectangle
(already used by src/rage_gauge.cpp); 1147d8 flat quad from four float points
(not reached by the gallery path); 113f98(a0=texture slot; f12=x, f13=y,
f14=z, f15=w, f16=h, f17=u, f18=v, f19=uw, stack float=vh) textured sprite,
modulated by the colour word 0x3db900.
Colour words are written here as raw 32-bit values 0xAARRGGBB-or-AABBGGRR;
the channel order is NOT resolved by this slice (UNKNOWN; the title-art
extractor's 1145c0/113f98 fixtures settle it).

W.2 Slide panel P (0x34 bytes; embedded in every widget)
--------------------------------------------------------
  +0x00 x current      +0x04 y current
  +0x08 frames left    +0x0c duration (frames)
  +0x10 x start        +0x14 y start
  +0x18 x target       +0x1c y target
  +0x20 closing flag (1 = target is the closed position)
  +0x24 x closed       +0x28 y closed
  +0x2c x open         +0x30 y open

  17f410(P, xClosed, yClosed, xOpen, yOpen, duration)   store +24,+28,+2c,+30,+0c only
  17f428(P, same five)   17f410, then 17f3a0(P, xClosed, yClosed), +20 = 1
  17f308(P)              17f428(P, 0,0,0,0, 1)
  17f3a0(P, x, y)        snap: cur = start = target = (x,y); frames left = 0
  17f508(P)              17f3a0(P, xClosed, yClosed)
  17f3c0(P, x, y, n)     start = cur; target = (x,y); +0c = +08 = n;
                         if cur == target then +08 = 0;  +20 = 0
  17f468(P)  OPEN        if target != open:   17f3c0(P, open, duration)   (+20 = 0)
  17f4b0(P)  CLOSE       if target != closed: 17f3c0(P, closed, duration); +20 = 1
  17f3f8(P)              +08 = 0
  17f400(P)              returns (+08 < 1): 1 when no animation is running
  17f330(P)  TICK, called once per frame:
      if (+08 > 0) {
          t = +08 - 1;  +08 = t;
          x = (t*xStart + (dur - t)*xTarget) / dur     // signed 32-bit, C division
          y = (t*yStart + (dur - t)*yTarget) / dur
          if (t > 0) return 2;                         // moving
      }
      return (+20 == 0) ? 1 : 0;                       // 1 = open/at rest, 0 = closed
  Linear interpolation; the frame on which t reaches 0 already returns 1/0.
  All panels in this part use duration 0x10 (16 frames).

W.3 Selector S (0x1c bytes; cursor + pad reader)
------------------------------------------------
  +0x00 flags    +0x04 disabled-item bitmap pointer (valid when flag 0x800)
  +0x08 min      +0x0c max (exclusive)     +0x10 step
  +0x14 current  +0x18 page size (0 = paging off)

  flag bits (20e0a0(S, bit, value) sets/clears 1<<bit; 20e088(S, bit) tests):
    bit 0  0x1      up/down move the cursor (pad repeat 0x10 / 0x20)
    bit 1  0x2      left/right move the cursor (pad repeat 0x40 / 0x80); tested first
    bit 2  0x4      wrap at both ends (otherwise clamp)
    bit 3  0x8      negate the movement delta
    bit 4  0x10     confirm is refused (returns 6)
    bit 5  0x20     cancel is refused (returns 6)
    bit 7  0x80     no sound on cursor movement
    bit 8/9 0x300   no sound on confirm / refusal
    bit 8/10 0x500  no sound on cancel
    bit 11 0x800    +4 points to a bitmap of disabled items (20e480 sets it;
                    20e498 tests, 20e4e0 sets, 20e528 clears one bit)
    bit 17 0x20000  confirm mask is 0x202 only (pad bit 0x8 is not a confirm)
    bit 18 0x40000  movement delta forced to 0 (cursor locked)
    bits 12, 13, 15, 16 are not read by the selector; the list widget uses
    them as its own mode bits (W.4).

  20dff8(S)  init: flags = 5 (up/down + wrap), cur = 0, then 20e028(S,0,1,1,0).
  20e028(S, min, max, step, page): if min == max then max += 1; if max < min
      swap; step 0 becomes 1; page kept only if page < max, else 0; then
      20e0d0(S, cur).
  20e0d0(S, v) set cursor with range fix-up:
      v <  min: cur = (flags&4) ? max-1 : min
      v >= max: cur = (flags&4) ? min   : max-1
      else cur = v

  20e128(S, seat) -> code.  pad = 118128(seat); pressed = pad[+4]; rep = pad[+8].
      old = cur
      confirm = (flags&0x20000) ? (pressed & 0x202) : (pressed & 0x8 || pressed & 0x202)
      cancel  = !confirm && (pressed & 0x404)
      if confirm:
          if (flags & 0x10) or item 'cur' is disabled (bitmap):
              if !(flags & 0x300) 1e7b70(-1, 0x24);   return 6
          if !(flags & 0x300) 1e7b70(-1, 0);          return 4
      if cancel:
          if (flags & 0x20): if !(flags & 0x300) 1e7b70(-1, 0x24);  return 6
          if !(flags & 0x500) 1e7b70(-1, 0x24);       return 5
      d = 0
      if flags&2: if rep&0x40 d = -step; else if rep&0x80 d = +step
      if flags&1 and d == 0: if rep&0x10 d = -step; else if rep&0x20 d = +step
      if flags&8 d = -d;   if flags&0x40000 d = 0
      cur = old + d
      if cur >= max: cur = (flags&4) ? min   : max-1
      else if cur < min: cur = (flags&4) ? max-1 : min
      if cur != old: if !(flags&0x80) 1e7b70(-1, 0x20);  return 1
      page = +0x18;  if page < 0 return 0
      if page > 0 and rep & 0x100000:  [sound 0x20 unless flag 0x80]
              cur = max(cur - page*step, 0);      return cur != old ? 2 : 0
      if page > 0 and rep & 0x400000:  [sound]
              cur = min(cur + page*step, max-1);  return cur != old ? 3 : 0
      if rep & 0x200000:               [sound]  cur = 0;      return cur != old ? 1 : 0
      if rep & 0x800000:               [sound]  cur = max-1;  return cur != old ? 1 : 0
      return 0
  The four paging/home/end branches request sound 0x20 even when the cursor
  does not change. Return codes: 0 idle, 1 moved, 2 page back, 3 page
  forward, 4 confirm, 5 cancel, 6 refused. The gallery tasks test 4, 5 and
  (code-1) < 3 unsigned (= any cursor change).
  Pad bit meaning (INFERRED from use): pressed 0x202 / 0x8 confirm, 0x404
  cancel; repeat 0x10 up, 0x20 down, 0x40 left, 0x80 right, 0x100000 /
  0x400000 page back / forward, 0x200000 / 0x800000 first / last. The
  0x118128 pad structure itself is specified in Part B.
